# «Код Урожая» — прототип ЦП АПК на LSfusion

Прототип цифровой платформы АПК «Код Урожая»: полный годовой контур
агроуправления (земельный банк → севооборот → техкарты → годовой план →
цены → МТР/БДР/БДДС → NPK-программирование урожая → симуляция →
корректирующие мероприятия → логистика → учёт урожая → DWH/витрины →
отчёты и панели → калибровка моделей) на платформе [LSfusion],
унаследованный от базового проекта MITE (IoT-мониторинг).

Геопривязка стенда — НПХ «Омское» (филиал Омского АГРАРНОГО НАУЧНОГО
ЦЕНТРА): реальные полигоны 10 земельных участков (1633 га) и 31 поля
(1430 га) с культурами 2027 и историей посевов 2023–2026.

Встроенная **интерактивная карта** (maptalks + кастомные JS-компоненты
LSfusion) реализует требования геоаналитики спецификации: тематические
раскраски (культура/урожайность/NDVI/агрохимия/договоры), кадастровый
слой, временной слайдер NDVI со стресс-динамикой, зоны дифференцированного
внесения (k-means), измерения и буферные (водоохранные) зоны, наблюдения
скаутинга, маршруты вывоза (VRP-решатель), мини-карты в карточках,
демо-RLS по организациям.

## Структура репозитория

| Путь | Содержимое |
|---|---|
| `sources/mite_public/` | Исходники приложения: `.lsf`-модули (`Ku*` — «Код Урожая», унаследованный MITE), Java-действия (k-means, ISOXML), `src/main/resources/web/` — JS-компоненты карты (`kumap.js`) и дашбордов (`kuhome.js`, ECharts) |
| `sources/mite_public/docs/` | Документация: спецификация и ТЗ (spec/tz), модель данных (02), логика модулей (03-*), эксплуатация (08), сценарии показа (11, 11a), развёртывание (12), интеграция KNP (13), контуры полей (14), конспекты внешних API (external-apis) |
| `docker/` | docker-compose и Dockerfiles: db (PostgreSQL+PostGIS), server, web (Tomcat), grafana, builder |
| `sql/` | Идемпотентные миграции: картография и демо-данные (01–12), снапшоты геометрии НПХ «Омское» |
| `knp_bridge/` | Python/FastAPI-мост к платформе KNP: REST-слоты economics/yield/simulation/ku, VRP-решатель (greedy+2-opt), конвертер переработки, тесты |
| `rebuild_logic.sh`, `backup_db.sh` | Скрипты пересборки логики и бэкапа БД стенда |

Платформа LSfusion — внешний git-клон (пин в `docs/12-deploy-guide.md`);
готовая сборка и дамп демо-БД передаются пакетом, в git не входят.

## Быстрый старт

Полная инструкция «от чистой ВМ ALT Server до работающего стенда»:
[`docs/12-deploy-guide.md`](sources/mite_public/docs/12-deploy-guide.md).
Кратко: `docker compose build` → `up -d db` → restore дампа (или чистая
БД + `sql/01..12`) → `up -d server web grafana` → `http://<IP>:8080/main`
(admin/fusion; демо-входы `demo.agronom`/`demo.banker`, пароль `demo`).

Сборка логики из исходников: клонировать платформу по пину, затем
`docker compose run --rm builder` (или `rebuild_logic.sh`).

`knp_bridge` + api-gateway KNP, ollama/OpenWebUI, AI-агент, neo4j,

## Версионирование

История ведётся от базового проекта MITE; вехи отмечены тегами
(`v1.0-*` — модули КУ, `v1.1-demo-passed` — приёмка демо,
`v1.2-unified-map` — единая карта, `v1.3-nph-omskoye` — геопривязка
к НПХ «Омское»: участки+поля+культуры+история).

## Условия

Прототип/демо-стенд. Учётные данные и пароли в docker-конфигурации —
демо-стендовые, публичных секретов в репозитории нет.
