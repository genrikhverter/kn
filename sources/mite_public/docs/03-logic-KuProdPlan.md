# 03-logic. KuProdPlan — годовой план и акт урожая (`ProdPlan.lsf`)

> Модель — `02-data-model.md` §5. Источник — СТ ФТ1.3.1–1.3.5 и блок
> «Акт учёта урожая» (ФТ1.5.1–1.5.4 по сквозной нумерации СТ). Статус: П.

## 1. Годовой производственный план

- `newProdPlan (Organization org, INTEGER year)`: NEW план (номер
  `ГП-<год>-<seq>`), `rotationPlan <-` последний утверждённый план
  севооборота org (CONSTRAINT: только approved); автозаполнение items:
  FOR полей org — `crop` из строки ротации на `planYear`, `areaHa` из
  поля; техкарта — подбор `GROUP MAX TechCard WHERE crop=... AND
  status=approved` (если нет — пусто, назначить вручную).
- Назначение ТК (ФТ1.3.2): на форме item выбирается карта (фильтр по
  культуре item и approved).
- Массовое назначение (ФТ1.3.3): `assignTechCardsBulk (plan)`: FOR items
  без карты → автоподбор по культуре; отчёт «назначено/пропущено» в
  ServiceLog.
- Утверждение (ФТ1.3.4): `approveProdPlan(p)`: предусловия — draft, все
  items имеют культуру и утверждённую ТК (CONSTRAINT с сообщением,
  сколько пустых); эффекты — approved, даты/утвердивший, комм.
- Просмотр (ФТ1.3.5): READONLY-форма утверждённого плана: поля ×
  (культура, площадь, ТК+версия, отклонения) + итог площади по культурам.
- Версионирование: копия «на основании» как в KuRotation (basedOn,
  version+1, старая → archived при утверждении новой).

## 2. Акт учёта урожая

- `newHarvestAct (ProdPlan p)`: NEW акт (номер `АУ-<год>-<seq>`, draft);
  предзаполнение items по полям плана: crop, planYield (из плана:
  targetYield культуры / 10 → т/га; ⚠ приведение ц/га→т/га).
- Ввод факта (ФТ1.5.2): валовой вес, влажность, сорность, класс,
  назначение, номер акта на току, источник данных.
- Расчётные (⚠ допущение прототипа — базовые значения влажности 14%,
  сорности 2% для зерновых; уточнить агрономом):
  `netWeight = grossWeight * (100 - moisture - impurity) / (100 - 14 - 2)`;
  `factYield = netWeight / areaHa`; `devAbs = factYield - planYield`;
  `devPct = devAbs / planYield * 100`.
- Проведение (ФТ1.5.3): `postHarvestAct(a)`: предусловия — draft, все
  строки заполнены; эффекты — posted, postedAt/By; обратная запись:
  `FOR items DO factYield(Field) <- factYield; lastCrop(field) <- crop`
  (история для севооборота следующего цикла).
- Анализ (ФТ1.5.4): форма-реестр + отчёт Jasper «Урожайность: план vs
  факт» по полям/культурам (KuAnalytics).

## 3. Валидации

`planYear` — следующий за текущим или поздее (прототип: 2027+);
items (plan, field) уникальны; moisture/impurity 0–100, grossWeight > 0;
акт — только по approved плану; проведение — все обязательные поля строк.

## 4. Сид

Годовой план 2027 по сид-ротации (все поля с ТК), approved; второй —
2028 draft с 2 полями без ТК (демо массового назначения). Акты: один
проведённый (отклонение −12% на одном поле — красный в отчёте), один
черновик.

## 5. Критерии приёмки

1. Автозаполнение из ротации корректно (культуры по годам).
2. Утверждение плана с «пустыми» назначениями блокируется с count.
3. Массовое назначение закрывает все дырки (или логирует причину).
4. Расчёт зачётного веса сходится на контрольном примере (10 т, 18%,
   4% → 8,448 т при базовых 14/2).
5. Проведение акта обновляет факт-урожайность и последнюю культуру поля.
