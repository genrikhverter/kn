# 03-logic. KuTechCard — логика технологических карт (`TechCard.lsf`)

> Модель данных — `02-data-model.md` §4. Источник — СТ ФТ1.2.1–1.2.6,
> «Программные интерфейсы» (sync-методы). Статус: П.

## 1. Действия и жизненный цикл (ФТ1.2.1–1.2.6)

- Создание (ФТ1.2.1): форма-редактор (карта + вложенные операции +
  материалы/ГСМ/трудозатраты по операции). При `NEW`: `status <- draft`,
  `version <- 1`, `author/createdAt` авто.
- Редактирование (ФТ1.2.2): только draft — READONLY-группы на форме +
  `CONSTRAINT WHEN CHANGED(свойств карты/операций) WHERE status != draft
  MESSAGE 'Утверждённая карта не редактируется — создайте новую версию'`.
- Утверждение (ФТ1.2.3): `approveTechCard (TechCard c)`:
  предусловия — draft, есть ≥1 операция; эффекты — `status <- approved`,
  `approvedAt/By` авто; запись в ServiceLog.
- Просмотр списка (ФТ1.2.4): реестровая форма с фильтрами (культура,
  статус, организация) — 04-ui.
- Копирование (ФТ1.2.5): `copyTechCard (c)`: новый draft, `basedOn <- c`,
  копия операций/материалов/ГСМ/трудозатрат, `version <- 1` (независимая
  ветка).
- Новая версия утверждённой (ФТ1.2.6): `newTechCardVersion (c)`:
  как копирование, но `version <- version(c) + 1`; при утверждении новой
  версии старая с тем же `crop+organization+номером ветки` → archived.

## 2. Валидации

1. `seqNo` операций: уникален в карте, ≥ 1 (CONSTRAINT).
2. Утверждение: ≥ 1 операция (`CONSTRAINT ... CHECKED BY`).
3. `validFrom <= validTo` (если заданы).
4. Нормы расхода/времени > 0; `workersCount >= 1` если задано.
5. Операции с `phaseTrigger`: фаза принадлежит культуре карты
   (`Phase.crop = TechCard.crop` — CONSTRAINT).
6. Материалы: номенклатура семян/удобрений/СЗР; ГСМ — номенклатура
   типа ГСМ (CONSTRAINT по `NomType`); `unit` берётся READONLY из
   номенклатуры (CONSTRAINT при попытке изменения).
7. `gapMinDays <= gapMaxDays`; `tempMin <= tempMax` (если обе заданы).

## 3. Расчётные свойства

- `opCount 'Операций' (TechCard c) = GROUP SUM 1 BY card`.
- `laborTotal 'Трудозатрат, ч/га' (c) = GROUP SUM timeRate(op) BY card`.
- `materialRate 'Материалов, ед/га'` — сводка для реестра: GROUP CONCAT
  по номенклатуре (⚠ из простых полей, §5.1 00-context).
- Стоимость/потребности — считает KuBudget (не дублировать здесь).

## 4. REST-ручки (статус У, sync-методы СТ)

- `apiTechCardCreate()`: вход {name, cropCode, operations[{workTypeCode,
  materials[], fuel[], labor[]}]} → создаёт draft со строками; ответ
  {cardId(code), version, status}.
- `apiTechCardApprove()`: вход {cardCode, comment} → утверждение или
  ошибка валидации; ответ {ok, version, approvedAt}.

## 5. Сид

3 карты (02 §4): «Пшеница озимая — Интенсивная 2.0» (approved, 9 операций:
вспашка→культивация→посев→2 подкормки→гербицид→фунгицид→уборка),
«Кукуруза — стандарт» (approved, 7 операций), «Пар сидеральный»
(draft, 3 операции). Материалы/ГСМ/трудозатраты — по 1–3 строки на
операцию, цены согласованы со сценарием цен KuBudget.

## 6. Критерии приёмки

1. Редактор: добавление операций/материалов, CONSTRAINT 1–7 срабатывают.
2. Утверждение черновика без операций блокируется.
3. «Новая версия» утверждённой: draft с version+1; после утверждения
   старая архивируется.
4. Реестр с фильтрами по культуре/статусу.
5. Обе REST-ручки работают через /exec.
