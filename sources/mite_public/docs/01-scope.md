# 01. Скоуп прототипа «Код Урожая», решения и трассировочная матрица

> Управляющий документ пакета: определяет, ЧТО делается в прототипе, где и
> с какой глубиной. Статусы из этого документа обязательны для этапов 2–4.
> Источник требований — «Спецификация требований к Цифровой платформе в
> сфере АПК „Код Урожая“», версия от 25.06.2026 (далее — СТ).

Статусы: **П** — полностью; **У** — упрощённо (с фиксацией допущения);
**К** — каркас (структура данных + статусы + формы, расчёты-заглушки);
**О** — отложено (обоснование — `05-deferred.md`).

## 1. Цель и рамки

Прототип платформы «Код Урожая» на базе MITE: реализуем на LSfusion всё, что
платформа закрывает штатно, на одинаковую глубину по всем пяти модулям СТ;
что штатно не закрывается (SPA, мобильные, оффлайн, ETL/DWH, VRP, ML,
трейсинг, требование 1С) — честно документируется в `05-deferred.md`.
Глубина по всем модулям — равномерная (решение заказчика от 2026-09-24).

## 2. Ключевые решения (ADR)

- **ADR-1. Отдельные модули, гармонизация с существующими.** Вся
  функциональность «Код Урожая» — в новых модулях `Ku*`; существующие модули
  MITE не переписываются. Переиспользование — через `REQUIRE` базовых
  модулей (Organization, Location, Weather, Scheduler, Telegram, Geo) и
  добавление `DATA`-свойств существующим классам только из новых модулей
  (паттерн «надстройка», эталон — `Agro.lsf` над `EquipmentUnit`).
  Расширение поведения существующих абстракций — через `+=`.
- **ADR-2. Единый NAMESPACE `Ku`** для всех новых модулей (по образцу
  StoreTask): сгруппированность без боли кросс-ссылок. Демо `Agro.lsf`
  остаётся как есть, нетронутым.
- **ADR-3. «Культура» — класс `Crop`** (не строка): справочник с
  агрономическими правилами (предшественники, период возврата, вегетация,
  требования к почве). Строковое `Agro.crop` демонстрационное, не мигрируем.
- **ADR-4. Земля — два класса**: `LandPlot` «Земельный участок»
  (юридический: кадастр, договоры) и `Field` «Поле» (агрономический рабочий
  участок: площадь, угодье, ссылка на `LandPlot`, история посевов).
  Координаты/география — через ссылку на `Location` (не наследование),
  полигоны — по образцу `Location.lsf:108` (Area/AreaPolygon).
- **ADR-5. Требование СТ о реализации модулей 1–2 как расширения
  1С:Предприятие 8 в прототипе НЕ выполняется** — реализуем на LSfusion;
  отступление фиксируется в `05-deferred.md` §1.
- **ADR-6. Расчётные методики, отсутствующие в СТ** (балансовый метод NPK,
  модель роста для симуляции, оптимизация графика обеспечения),
  формулируются упрощённо автором документации с явной пометкой
  «⚠ допущение прототипа — требует уточнения агрономом» (решение заказчика).
- **ADR-7. UI**: только штатные формы LSfusion; интерактивная матрица
  севооборота — штатная табличная форма (поля × годы). SPA- и мобильные
  формы СТ — отложены; вместо них при дешевизне делаются REST-ручки
  (`/exec?action=...`) для будущего внешнего фронта.
- **ADR-8. Язык**: документация и подписи — русские; идентификаторы — англ.
- **ADR-9. Демо-данные** — сиды по эталону `agroSeed` (`Agro.lsf:486`,
  `00-context.md` §4.5): guard `Mite.standMode()`, идемпотентность.
- **ADR-10. Контрагенты** — собственный класс `Contractor` (юр/физлица по
  СТ), связывается с `Organization` опционально; `Organization` — только
  «наши» организации холдинга.

## 3. Новые модули (волны реализации — §7)

| Модуль / файл | Раздел СТ | Ключевые сущности | REQUIRE (из существующих) |
|---|---|---|---|
| `KuCrop` / `Crop.lsf` | НСИ культур | Crop (культуры, сорта), правила севооборота (предшественники, период возврата) | Utils, SystemEvents |
| `KuLand` / `Land.lsf` | Земельный банк | LandPlot, Field, Contractor, аренда (Contract, Payment), агрохиманализ (SoilAnalysis) | Location, OrgLocation, Organization, Geo, Country |
| `KuRotation` / `Rotation.lsf` | Долгосрочный план севооборота | RotationPlan + строки (поле × год × культура), версии, статусы, валидации | KuCrop, KuLand |
| `KuTechCard` / `TechCard.lsf` | Техкарты | TechCard, операции, материалы/ГСМ/трудозатраты; справочники: виды работ, фазы, методы внесения, ед. изм., профессии | KuCrop, Organization |
| `KuProdPlan` / `ProdPlan.lsf` | Годовой план, акт урожая | ProdPlan (назначение ТК полям), HarvestAct | KuRotation, KuTechCard, KuLand |
| `KuBudget` / `Budget.lsf` | Сценарии цен, бюджеты | PriceScenario, МТР-потребность, БДР, БДДС; справочники: номенклатура, условия оплаты, статьи затрат | KuTechCard, KuProdPlan |
| `KuYield` / `Yield.lsf` | Программирование урожая | интерактивный NPK-расчёт (балансовый, упрощ.), корректирующие мероприятия, окна работ, привязка к погоде/датчикам | KuCrop, KuLand, Weather, WeatherOpenWeatherMap, Measurement |
| `KuSimulation` / `Simulation.lsf` | Симуляция | SimTask (жизненный цикл), упрощённая модель роста (GDD), сценарный анализ | KuRotation, KuLand, KuProdPlan, Scheduler |
| `KuAnalytics` / `Analytics.lsf` | Отчётность (в части прототипа) | Jasper-отчёты + Grafana-дашборды по данным Ku* | GrafanaDashboard, Ku* по необходимости |

Подключение: каждый новый модуль добавляется в `REQUIRE` зонтика `MiteApp`
(или отдельного `KuApp`-зонтика, подключаемого в `MiteApp`) — финальную
схему сборки зафиксировать в `02-data-model.md`.

## 5. Маппинг экранных форм СТ (36 форм)

**Реализуем штатными формами LSfusion:**
UI-101/102 (реестр и карточка участка), UI-103/104 (реестр и карточка
договора), UI-105 (агро-сводка по землям; полная карта — О), UI-106
(агрохиманализ), UI-201/202 (сценарии цен), UI-203 (матрица севооборота —
штатная таблица), UI-204/205 (реестр и редактор техкарт), UI-206 (годовой
план), UI-207 (бюджетные отчёты), UI-301 (NPK-калькулятор упрощённо),
UI-302/303 (график МТР, задания — К), UI-401/402/403 (панель задач
моделирования, очередь, результаты), UI-502 (библиотека отчётов),
UI-604 (RBAC — уже есть в платформе, расширить ролями «Код Урожая»),
UI-701 (ведомость справочников — папка справочников Ku*), UI-702
(глоссарий — статическая форма-справка).

**Частично/заменителями:**
UI-001–004 (SPA-оболочка → штатный веб-клиент MITE с навигатором),
UI-503/504 (дашборды → Grafana, паттерн MITE), UI-601 (мониторинг →
ProcessMonitor платформы).

**Отложено (О, см. `05-deferred.md`):** UI-501 (конструктор отчётов),
UI-602/603 (журнал событий/трейсинг), UI-801/802 (мобильные приложения).

## 7. Волны реализации (порядок для этапов 2–4 и генерации)

1. **НСИ и земля**: KuCrop, KuLand — фундамент для всего.
2. **Ядро планирования**: KuRotation (валидации севооборота — центральная
   демо-сценарий прототипа), KuTechCard.
3. **Планы и урожай**: KuProdPlan, KuYield.
4. **Деньги и модели**: KuBudget, KuSimulation.
5. **Аналитика и API**: KuAnalytics, REST-ручки (KuRotation и др.).

Внутри волны: сначала `02` (данные), затем `03` (логика), затем `04`
(формы) — по одному модулю за сессию генерации (см. `06-generation-guide.md`).
