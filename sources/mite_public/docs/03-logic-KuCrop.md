# 03-logic. KuCrop — логика справочника культур (`Crop.lsf`)

> Модель данных — `02-data-model.md` §1. Источник — СТ «Справочник
> сельскохозяйственных культур» (`spec-source.md`). Эталалоны кода —
> `00-context.md` §4–5.

## 1. Покрытие

НСИ культур с правилами севооборота. Статус по `01-scope.md`: П.
Ключевой потребитель валидаций — KuRotation; агрономические
коэффициенты — KuYield/KuSimulation.

## 2. Действия

- Создание/редактирование — штатные `NEW/EDIT` на форме (конвенция
  `00-context.md` §4.3). При `NEW`: `status <- 'Активен'`,
  `created <- currentDateTime()`, `createdBy <- currentUser()`.
- `archiveCrop 'Архивировать' (Crop c)`: `status(c) <- 'Архив'`.
  CONSTRAINT: нельзя архивировать культуру, используемую в строках
  действующих (неархивных) планов севооборота и техкарт.
- Реестры `CropPredecessor`/`CropTaboo` — редактирование на форме
  культуры (вложенные объекты).

## 3. Валидации (CONSTRAINT ... CHECKED BY ... MESSAGE)

1. Уникальность: `code` (GROUP AGGR / CONSTRAINT), `registryCode`.
2. `returnYears >= 1`.
3. Диапазоны: `phMin <= phMax`, `humusMin <= humusMax`, `nMin <= nMax`
   (аналогично P, K), `moistMin <= moistMax`, `tempMin <= tempMax` —
   только когда обе границы заданы.
4. ⚠ отклонение (зафиксировано в коде): само-предшественник и само-табу
   РАЗРЕШЕНЫ — «подсолнечник нельзя после подсолнечника» выражается именно
   само-табу; «пшеница после пшеницы» при возврате 1 год — само-предшественник.
5. Одна и та же культура-предшественник не может быть одновременно
   допустимой и запрещённой для культуры: CONSTRAINT на пару
   (crop, predecessor) в обоих реестрах.
6. `vegetationDays >= 1`.

## 4. Вычисляемые свойства

- `nameCrop 'Культура (с сортом)' (Crop c) = name(c) + ' ' + variety(c)`
  — для выпадающих списков в планах.
- `isArchived (Crop c) = status(c) = 'Архив'` — базовый фильтр выбора
  («действующие») во всех селекторах Ku*.
- `allowedAfter 'Можно после' (Crop c) = GROUP CONCAT name(predecessor(p))
  ORDER predecessor(p)` по `CropPredecessor` — всплывающая подсказка в
  матрице севооборота (⚠ собирать из простого поля `name`, см.
  `00-context.md` §5.1).

## 5. Интеграции

Нет REST-ручек. `geneticCoeffs` (TEXT, JSON) и агрономические диапазоны
читаются KuYield (балансовый метод) и KuSimulation (модель роста).
Загрузка из Госреестра — вне прототипа (`05-deferred.md`).

## 6. Сид (`cropSeed`, вызов из KuApp-сида, см. `06-generation-guide.md`)

10 культур (пшеница озимая, ячмень, кукуруза, подсолнечник
`returnYears=4`, рапс, соя, сахарная свёкла, картофель, томат, пар
«Чистый пар»), правила: паслёновые (картофель ↔ томат) — взаимное табу;
зерновые после зерновых допустимы с периодом возврата 2; подсолнечник —
табу после подсолнечника/рапса. Guard: `IF NOT (GROUP MAX Crop c)`.
Значения N/P/K-диапазонов и выносов — согласованы с сидами KuYield.

## 7. Критерии приёмки

1. Форма культур: создание, редактирование реестров предшественников.
2. CONSTRAINT 3 и 4 воспроизводятся на демо-данных (сообщение по-русски).
3. Сид идемпотентен (повторный `onStarted` не дублирует).
4. В селекторах KuRotation/KuTechCard архивные культуры не видны.
