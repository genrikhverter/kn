## 2. Спецификации ключевых форм

### `landPlots` / `landPlot` (UI-101/102)
Реестр: OBJECTS p=LandPlot; колонки: name, cadastralNumber, areaSqm,
plotStatus, арендодатель (GROUP MAX по договорам), dateTo действующего
договора, `stateMark` (расч. '⚠ истекает/✖ просрочено' из 03-logic
KuLand §5); FILTERS organization, plotStatus; панель NEW/EDIT/DELETE +
`PRINT` «Земельный банк». Карточка: вкладки — «Основное» (реквизиты,
егрнExtract), «Договоры» (вложенный объект LeaseContract по участку),
«Агрохимия» (SoilAnalysis по полям участка), «Поля» (Field через
FieldPlot), «История» (rotationHistory полей).

### `leaseContracts` / `leaseContract` (UI-103/104)
Реестр: номер, tenant/landlord, plot, dateFrom/dateTo, status,
`balance`, `stateMark`; цветовая индикация — строкой-маркером (см. §3).
Карточка: реквизиты договора; вкладка «Платежи» (LeaseEntry: дата, вид,
сумма) + блок сальдо (obligationSum/paymentSum/balance/overdue);
кнопки-действия: `accrueRent`, `registerPayment`,
`buildPaymentSheet`, `PRINT` «Сальдо аренды»; вкладка «Уведомления»
(LeaseNotification).

### `rotationPlan` — матрица севооборота (UI-203)
OBJECTS i=RotationPlanItem (FILTERS plan = выбранный план в шапке);
PROPERTIES: поле, площадь; матрица — `crop(i,1)..crop(i,horizon)`
редактируемые при draft (заголовки колонок — `yearOf(i,1)..`: 
динамические подписи через nameCrop-подобные свойства; горизонт 5 —
колонки фиксированные 1..5, при horizon>5 — вторая группа). Под каждой
годовой колонкой READONLY `violationMark(i,y)` ('✖'/'⚠'). Тултип
нарушения: колонка `violationText` или отдельная панель выбранной
строки. Итоговая строка: `GROUP SUM areaHa BY crop` на каждый год —
отдельная панель «Площади по культурам». Кнопки: «Проверить»
(validateRotationPlan), «Утвердить» (approveRotationPlan), «Копия/
новая версия», PRINT «План севооборота». Реестр `rotationPlans`:
номер, годы, статус, версия, крит-нарушения count.

### `techCard` (UI-205)
Шапка: name, crop, статус, версия, validFrom/To, описание. Вкладка
«Операции»: OBJECTS o=TechOperation (seqNo, workType, phaseTrigger,
сроки, интервалы, t°, норма) — мастер-детейл: под выбранной операцией
три подтаблицы: материалы / ГСМ / трудозатраты (по образцу
мастер-детейл форм MITE). READONLY-все при status ≠ draft. Кнопки:
Утвердить, Копировать, Новая версия. «Итоговая стоимость на 1 га» —
сводная строка по ценам последнего утверждённого сценария
(расчётное свойство, дублировать не в KuBudget).

### `prodPlan` (UI-206)
Шапка: год, статус, версия, rotationPlan. Таблица назначений: поле,
площадь, культура, техкарта (+версия), отклонение. Кнопки:
Автозаполнение, Массовое назначение ТК, Утвердить; итоги: площадь,
`laborTotal`, потребность семян (GROUP SUM rate×area по типу семена).

### `budgets` (UI-207)
Шапка: prodPlan + priceScenario + кнопки «Рассчитать МТР/БДР/БДДС»,
«Утвердить». Вкладки: МТР (месяц × номенклатура × qty), БДР (статья ×
месяц × сумма; итоги доход/расход/маржа), БДДС (месяц, вид, сумма,
source, paymentTerm; `runningBalance`), «Сравнение сценариев» (по
03-logic KuBudget §5). Кнопка PRINT по вкладке.

### `complexPlan` — калькулятор NPK (UI-301)
Панель параметров: поле (список с поиском), культура, variety (строка),
priceScenario, targetYield, soilAnalysis (READONLY-последний по полю),
кнопка «Рассчитать» (recalcNutrients), «Что-если» (пересчёт без
сохранения), «Утвердить» → сезонная ТК. Таблица NutrientBalance:
элемент × вынос × запас × усвоения × потребность. Экономика:
доход/затраты/marginPercent + warnings (панель). Вкладка «Сезонная
карта» (SeasonalTechCard с операциями/материалами) + кнопка
«Предписание (JSON)».

### `simTasks` / `simResults` (UI-401–403)
Реестр задач: поле, taskKind, статус, plannedAt, horizon, ошибки;
кнопки: Запустить (runSimTask), Отменить. Реестр результатов:
forecastKind, поле, культура, calcAt, yieldForecast(последняя точка),
status; карточка: шапка + OBJECTS SimResultPoint (дата, биомасса, NDVI,
фаза, вода, N/P/K, прогноз) ORDERS pointDate; кнопка «Сценарный прогон»
(NEW ScenarioRun с параметрами по scenarioKind — INPUT-диалог).

### `kuHome` (UI-002)
HTML-KPI-панель по образцу `Agro.lsf:298`: площадь по культурам,
планы/бюджеты по статусам, сальдо аренды, отклонения урожайности,
активные симуляции + ссылки-навигация. ⚠ агрегаты лёгкие, из простых
полей (00-context §5).

## 3. Условное форматирование и «цвета»

Штатный веб-клиент LSfusion: цветовыделение ячеек — ограниченно.
Единый приём прототипа: расчётная колонка-маркер ('✖'/'⚠'/'') рядом с
данными + фильтр по ней; при генерации проверить доступность
`BACKGROUND`-механизма форм (если платформа 7.0 поддерживает фоны
свойств — использовать, зафиксировать в одном месте и переиспользовать).

## 4. Навигатор

Новая корневая папка (в NAVIGATOR рядом с `monitoring` из Base):
```
NEW FOLDER ku 'Код Урожая' WINDOW toolbar {
  NEW kuHome;
  NEW FOLDER kuLandFolder 'Земля' { landPlots; leaseContracts; soilAnalyses; }
  NEW FOLDER kuPlanFolder 'Планирование' { rotationPlans; techCards; prodPlans; }
  NEW FOLDER kuMoneyFolder 'Бюджеты' { priceScenarios; budgets; }
  NEW FOLDER kuYieldFolder 'Урожай' { complexPlans; optimizationSessions; routingTasks; }
  NEW FOLDER kuSimFolder 'Симуляция' { simTasks; simResults; }
  NEW FOLDER kuNsiFolder 'НСИ' { crops(культуры); workTypes; phases; nomenclatures; units; methods; professions; contractors; costItems; paymentTerms; stressTypes }
  NEW kuGlossary;
}
```
Справочники НСИ — формы из модулей-владельцев сущностей (KuCrop/KuTechCard/KuLand/KuBudget/KuSimulation).

## 5. Роли и права (доработка UI-604)

Новые UserRole-признаки по образцу `isLogist` (`Mite.lsf:14`):
`isAgronomist 'Агроном'`, `isLandManager 'Специалист по земле'`,
`isPlanner 'Планирование'`, `isModeler 'Агромоделирование'` —
SHOWIF-скрытие папок навигатора (земля/планы/бюджеты/симуляция);
администратор видит всё. Сид: роли создаются onStarted c
fillDefaultAccess.

## 6. Критерии приёмки

1. Все формы из §1 со статусом П/У/К открываются из навигатора.
2. Матрица севооборота: редактирование ячеек, маркеры нарушений,
   блокировка после утверждения.
3. Мастер-детейл техкарты (операция → материалы/ГСМ/труд) работает.
4. Роли скрывают чужие папки (проверка под тестовым пользователем).
5. kuHome показывает агрегаты сид-данных без деградации времени
   открытия (<3 c на стенде).
