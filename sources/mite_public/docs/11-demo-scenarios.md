# 11. Сценарии показа системы для двух аудиторий: «Агроном» и «Банкир»

> Проект демонстрации возможностей прототипа «Код Урожая» живьём в веб-клиенте.
> Опирается на отчётную презентацию гранта (этап 3, на 01.10.2026,
> `01-_-_3-2026_-1.pptx`) — показ должен усиливать её тезисы, а не противоречить им.
> Статус: v0.4, 03.10.2026 (вечер). **Оба сценария прогнаны на живом веб-клиенте
> под demo.agronom и demo.banker** (см. §9). v0.3 — пессимистичный сценарий со
> стресс-БДР, шаблон «Кредитная справка», демо-пользователи; v0.2 — Волна 4.
> Поле-герой KH-001 = «Северное-1» (в реестрах видно имя, не код).

## 1. Что доказывает показ

Отчётная презентация заявляет (слайды 3–6):

- платформа **полного жизненного цикла АПК**: от земли до сбыта, единое
  экономическое пространство для «производственных и финансово-экономических
  показателей»;
- **извлечение скрытых знаний** из разнородных источников — от бортовых
  компьютеров техники до ФГИС — правилами и обученными моделями;
- интеллектуальный ассистент **«ИИ-Агроном»**;
- сегменты взаимодействия: фермеры (доступ к финансированию!), холдинги,
  переработчики, регуляторы (слайд 5 — «Профили взаимодействия»);
- потенциальные операторы платформы — «Агропромцифра», **Россельхозбанк**, VK, 1С;
  федеративный принцип, коммерциализация (слайд 6).

Живой показ на нашем стенде закрывает два разных «фронта убеждения»:

| Аудитория | Что хочет увидеть | Что доказываем |
|---|---|---|
| **Агроном** (агрономы, гл. агрономы, хозяйства-пилоты из слайда 6) | «Система говорит на моём языке и экономит моё время» | Предметную глубину: севооборот с реальными правилами, NPK-баланс, зонирование, предписания для техники, модель роста, раннее выявление стрессов |
| **Банкир** (Россельхозбанк / кредитные аналитики АПК / инвестор) | «Я вижу деньги, риски и правду» | Прозрачность заёмщика: залоговая база, обязательства, бюджеты, P&L, раннее предупреждение риска урожая, аудит и верифицируемость данных, API |

Оба показа идут **по одному и тому же демо-холдингу** (10 полей, 5 договоров,
сезон 2027) — это само по себе тезис: «один источник правды для агронома и
финансиста». Отличается оптика и маршрут.

## 2. Общие принципы

1. **Живой показ в веб-клиенте** — основа; слайдов не более 3–4 (рамка «кто мы»
   из отчётной презентации + финальный слайд контактов). Всё остальное — экран.
2. **Сквозная драматургия «один сезон»**: показ строится как история сезона
   (план → программирование → прогноз → стресс → коррекция → уборка → деньги),
   а не как обзор меню. Навигатор показываем как «всё в одном окне», не ходя по
   нему экскурсией.
3. **Управление по отклонениям** — главный слоган показа: система считает всё
   сама (ночь, 01:00, регламентные задания), человек смотрит только туда, где
   загорелось. Каждую сцену заканчиваем фразой «…и агроном/финансист видит это
   в списке дел на сегодня, а не ищет сам».
4. **Один герой-поле на весь показ**: KH-001 (факт-NDVI −28% от эталона —
   сид-данные уже готовы). Зритель запоминает судьбу конкретного поля.
5. **Роли как фича**: для агронома входим под `demo.agronom` (роль «КУ:
   Агроном»), для банкира — `demo.banker` («КУ: Экономист» + «КУ: Руководитель»);
   пароль у обоих — `demo`. Переключение ролей показываем один раз как
   механизм разграничения (вход под ролью скрывает чужие разделы).
6. **Тайминг**: агроном ~30 мин + вопросы; банкир ~20 мин + вопросы.
7. **Каждый шаг имеет Plan B** (см. §6) — стенд демонстрационный, падения
   не прощают импровизации.

| А9 | Урожай → Корректирующие рекомендации | KH-001: тип стресса «Дефицит азота» → рекомендация из базы знаний (препарат, доза, экономика) → утверждение → операция в сезонной ТК | «Это наш „ИИ-Агроном“: событие → диагноз → рекомендация → действие в техкарте. совмещённый.

## 10. Единая карта v3 — двусторонняя связность (04.10, после тега v1.1-demo-passed)

Стек не менялся (maptalks + CUSTOM-компонент — «единая карта», решение
заказчика от 04.10); карта стала центром навигации, а не отдельным экраном:

| Связь | Как работает |
|---|---|
| Клик по полю на карте → карточка поля | `controller.change({action:'select'})` → ON CHANGE `kuMapClientEvent` (KuLand) → выбор зафиксирован (APPLY) → `SHOW fieldCard` |
| Выбор → подсветка ★ | `kuMapSelected` → секция `SEL` в снапшоте → золотая обводка + зум на поле (синхронизация при возврате на вкладку карты; мгновенная локальная подсветка — в JS) |
| Стресс → тема «По стрессу» | ABSTRACT-хук `kuFieldStress` (KuLand) ← реализация в KuSimulation (отклонение NDVI > порога); 12-е поле снапшота; красные поля + пунктирная обводка |
| NPK-зоны → слой карты | ABSTRACT-хук `kuFieldZones` ← KuYield (последний zonesJson k-means); секция `ZONES`; полигоны зон с дозами в попапах, чекбокс «Зоны внесения N» |
| Договоры → тема «По статусу договора» | 11-е поле снапшота — статус участка (раньше тема не работала: статус не передавался) |
| Формы → карта | «Показать на карте» в реестре полей, карточке участка, комплексных планах, результатах моделирования |
| Актуальность | кнопка «Обновить карту» на форме + пересборка при старте; клик тоже обновляет снапшот |

Уроки платформы: реализации ABSTRACT-свойств — слитное `+=` (`+ =` парсится
