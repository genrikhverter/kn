# 06. Регламент генерации кода для GLM

> Как по этому пакету генерировать код: порядок, постановка задач,
> приёмка, коммиты, откат. Обязателен к прочтению перед каждой сессией
> генерации вместе с `00-context.md`.

## 1. Пакет документации

| Документ | Роль |
|---|---|
| `00-context.md` | вход: архитектура MITE, конвенции, ловушки, цикл сборки |
| `01-scope.md` | что делаем/не делаем; ADR; глоссарий; волны |
| `02-data-model.md` | классы/свойства всех Ku-модулей |
| `03-logic-Ku<Модуль>.md` | поведение: действия, валидации, формулы, сиды |
| `04-ui.md` | формы и навигатор |
| `05-deferred.md` | что сознательно не делаем (не «забыли») |
| `spec-source.md` | исходная спецификация (эталон требований) |

## 2. Схема сборки (фиксируется здесь, ОТКРЫТО-2 из 01-scope закрыто)

- Новые файлы: `src/main/lsfusion/ku/KuCrop.lsf`, `KuLand.lsf`,
  `KuRotation.lsf`, `KuTechCard.lsf`, `KuProdPlan.lsf`, `KuBudget.lsf`,
  `KuYield.lsf`, `KuSimulation.lsf`, `KuAnalytics.lsf`, `KuApp.lsf`.
- `KuApp` — зонтик: `REQUIRE` всех девяти; подключается одной строкой
  в `MiteApp.lsf`: `REQUIRE KuApp;` (после существующих).
- Внутренние зависимости (порядок REQUIRE в KuApp):
  KuCrop → KuLand → KuRotation → KuTechCard → KuProdPlan → KuBudget →
  KuYield → KuSimulation → KuAnalytics. Циклы запрещены
  (`00-context.md` §3.4).
- Общий сид: `kuSeed()` в KuApp — последовательный вызов сидов модулей
  (каждый со своим guard); вызов в `onStarted() KuApp + { IF
  Mite.standMode() THEN kuSeed(); }`.
- Роли: признаки ролей (04-ui §5) — в KuApp (одним блоком).

## 3. Порядок сессий генерации (одна сессия = один модуль)

| # | Сессия | Документы | Выход |
|---|---|---|---|
| 1 | Каркас + KuCrop | 00, 02 §1, 03-KuCrop | файлы ku/, KuCrop.lsf, KuApp (частично), справочник культур |
| 2 | KuLand | 02 §2,§7; 03-KuLand | земля/договоры/аренда/анализы |
| 3 | KuRotation | 02 §3; 03-KuRotation | матрица, валидации, REST |
| 4 | KuTechCard | 02 §4; 03-KuTechCard | ТК + 6 справочников |
| 5 | KuProdPlan | 02 §5; 03-KuProdPlan | годовой план, акты |
| 6 | KuBudget | 02 §6; 03-KuBudget | цены, МТР, БДР/БДДС |
| 7 | KuYield | 02 §8; 03-KuYield | NPK, сезонные ТК, коррекции |
| 8 | KuSimulation | 02 §9; 03-KuSimulation | задачи, модель, сценарии |
| 9 | KuAnalytics + UI-полировка | 02 §10; 03-KuAnalytics; 04 | отчёты, kuHome, навигатор/роли |

Внутри сессии порядок: (а) DATA-классы/свойства → (б) действия/
валидации → (в) формы + навигатор → (г) сид → (д) пересборка и приёмка.
Формы модуля — по `04-ui.md` §1–2 (спецификации конкретных форм);
справочные формы НСИ — простые реестры.

## 4. Шаблон постановки задачи (промпт сессии)

```
Прочитай docs/00-context.md, docs/02-data-model.md §<N>,
docs/03-logic-Ku<Модуль>.md, docs/04-ui.md <разделы форм>.
Реализуй модуль Ku<Модуль> в src/main/lsfusion/ku/Ku<Модуль>.lsf
по этим спецификациям: данные, логика, формы, сид.
Конвенции и ловушки — 00 §4–5; не трогать 00 §6.
После реализации: rebuild_logic.sh, устрани ошибки, продемонстрируй
критерии приёмки из 03-Ku<Модуль> §<приёмка>, закоммить в fossil.
```

Правила для генератора:
- отклонения от 02/03 допустимы только по техническим причинам
  платформы — фиксировать комментарием `// ⚠ отклонение от 02 §...: ...`
  и сообщить в ответе сессии;
- русские подписи, английские идентификаторы; NAMESPACE Ku;
- каждый класс — TABLE; CONSTRAINT-сообщения по-русски;
- никаких тяжёлых GROUP CONCAT из CASE/OVERRIDE (00 §5.1) — при
  необходимости императивная сборка по образцу `Agro.lsf:344`;
- формулы с «⚠ допущение» реализовывать дословно из 03-logic,
  константы — в ModelCoeff/Options, не в коде.

## 5. Приёмка (DoD каждой сессии)

1. `rebuild_logic.sh` — без ошибок компиляции; сервер стартует,
   исключений в логе нет (`00-context.md` §2).
2. Критерии приёмки из раздела «Критерии приёмки» соответствующего
   03-logic — выполнены и описаны в ответе сессии (как проверено).
3. Сид идемпотентен: рестарт сервера не дублирует данные.
4. Формы модуля в навигаторе `ku` (04-ui §4), роли скрывают чужое
   (с сессии 9 — полноценно, раньше — заглушка).
5. `fossil commit` с сообщением «Ku<Модуль>: <суть> (сессия N)».

## 6. Откат и повторная генерация

- Ошибка сессии: `fossil revert` файлов сессии (или `fossil checkout`
  предыдущего чекина), повторная генерация с уточнённой постановкой.
- Частичный успех: чинить точечно, не перегенерировать весь модуль.
- Логи сборки: сохранять ключевой фрагмент ошибки в ответе сессии
  (для накопления знаний о ловушках платформы).
