# 07. Сквозной сезонный цикл (замкнутый контур)

> Документ заполняет пустой раздел спецификации «Описание сквозного
> процесса использования системы» и переупорядочивает ПМИ. Основан на
> фактической реализации прототипа (модули Ku* на LSfusion).

## Сезонный цикл

```
    ┌─────────────────────────────────────────────────────────────────┐
    │                                                                 │
    ▼                                                                 │
[1. Земля]──→[2. Севооборот]──→[3. Техкарты]──→[4. Годовой план]──→[5. Бюджет]
 участок, поле   матрица 5 лет     операции,       культура + ТК       МТР, БДР,
 договор,        (утверждение)     нормы           (утверждение)       БДДС
 агрохимия                                                          │
                                                                     ▼
[9. Акт урожая]◀──[8. Уборка]◀──[7. Прогноз]◀──[6. NPK-план]
 факт, зачётный     поле, т/га     симуляция,      комплексный план,
 вес, отклонение                  сценарии        баланс NPK,
                                  (базовый +      сезонная ТК,
                                  «что если»)     предписание
    │
    └──→ lastCrop(field) обновлён → следующий план севооборота ────→ [2]
```

## Шаги цикла: сущности, статусы, переходы

| № | Шаг | Сущность | Статус «готово» | Следующий шаг |
|---|---|---|---|---|
| 1 | Земля: участок + поле + договор | `LandPlot`, `Field`, `LeaseContract` | поле с площадью и культурой | создать план севооборота |
| 2 | Севооборот: матрица 5 лет | `RotationPlan` | `approved` (критических нарушений нет) | подобрать техкарты |
| 3 | Техкарты: операции + нормы | `TechCard` + операции/материалы/ГСМ/труд | `approved` (есть операции) | сформировать годовой план |
| 4 | Годовой план: поле + культура + ТК | `ProdPlan` + `ProdPlanItem` | `approvedG` (все назначения с ТК) | рассчитать бюджет |
| 5 | Бюджет: МТР → БДР → БДДС | `MtrPlan`, `BudgetPL`, `BudgetCF` | `approved` (БДР утверждён) | запрограммировать урожай |
| 6 | NPK: баланс + сезонная ТК | `ComplexPlan`, `NutrientBalance`, `SeasonalTechCard` | `approvedY` (утверждён) | запустить прогноз |
| 7 | Прогноз: симуляция роста | `SimTask` → `SimResult` | `active` (результат актуален) | сформировать предписание |
| 8 | Уборка: акт учёта урожая | `HarvestAct` + `HarvestActItem` | `posted` (проведён) | обновить севооборот |
| 9 | Замыкание: факт → поле | `Field.lastCrop`, `Field.factYield` | `lastCrop` обновлён | → шаг 2 следующего цикла |

## Роли и ответственность по шагам

| Шаг | Роль | Действие |
|---|---|---|
| 1. Земля | Специалист по земле | заведение участков, договоров, контроль сроков |
| 2. Севооборот | Агроном / Планировщик | матрица культур, проверка нарушений, утверждение |
| 3. Техкарты | Агроном | библиотека операций и норм |
| 4. Годовой план | Планировщик | назначение ТК полям, массовое назначение |
| 5. Бюджет | Планировщик / Экономист | расчёт МТР/БДР/БДДС, сценарный анализ |
| 6. NPK | Агроном | интерактивный расчёт, утверждение → сезонная ТК |
| 7. Прогноз | Агромоделирование | симуляция, сценарный анализ |
| 8. Акт урожая | Агроном | факт, зачётный вес, отклонения |
| 9. Замыкание | Система | обновление `lastCrop`, `factYield` полей |

## Переупорядоченный порядок ПМИ

| Порядок | КП | Проверяет | Почему здесь |
|---|---|---|---|
| 1 | КП07 | Земельный банк: участки + договоры | первый шаг — без полей нечего планировать |
| 2 | КП01 | План севооборота на 5 лет | распределяем культуры по полям |
| 3 | КП02 | Библиотека техкарт | готовим технологию для культур |
| 4 | КП03 | Годовой производственный план | назначаем ТК полям на год |
| 5 | КП04 | Бюджетирование | считаем деньги |
| 6 | КП10 | NPK + калибровка + предписание | оптимизируем дозы, готовим задания |
| 7 | КП05 | Прогноз роста | симулируем результат |
| 8 | КП06 | Сценарный анализ «что если» | проверяем альтернативы |
| 9 | КП08 | Аналитические панели | мониторим ход сезона |
| 10 | КП09 | Интерактивная карта | визуализируем географию |
| 11 | **КП11 (новый)** | **Акт урожая + замыкание цикла** | фиксируем факт, обновляем поля → следующий цикл |

## Отсутствующий КП11 (акт урожая) — что проверять

1. Пользователь переходит в экранную форму актов урожая.
2. Создаёт акт, выбирая утверждённый годовой план.
3. Вводит фактические данные по полям (валовой вес, влажность, сорность).
4. Система рассчитывает зачётный вес и отклонение от плана.
5. Пользователь проводит акт.
6. Система обновляет фактическую урожайность и последнюю культуру полей.
7. Пользователь создаёт план севооборота на следующий период — предшественники уже обновлены.
